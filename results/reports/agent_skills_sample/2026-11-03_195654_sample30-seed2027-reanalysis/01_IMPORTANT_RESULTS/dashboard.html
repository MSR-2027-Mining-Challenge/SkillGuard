Limitations and incomplete results

  • No security alert has been validated by a human yet. All 11 distinct alert locations are Cisco scanner output; none of them is a confirmed vulnerability.
  • 11 alert location(s) carry a *provisional* label. These are researcher-approved, AI-assisted decisions, not independent human-review results, and must not be reported as validated.
  • 6 configuration(s) were excluded by design: GitSkills did not store every supporting file of 3 skill(s), so their full-folder scans were not run. Those skills drop out of the SKILL.md-only vs full-folder comparison.
  • 4 partial and 0 contract-only scan(s) are kept but excluded from the primary analysis (see the status definitions); their findings appear only as preliminary / sensitivity evidence.
  • Most finding rows (114 of 141) are metadata-quality notes (missing license, vague description, ...), not security alerts. "Skills with findings" therefore overstates security exposure; use skills with security alerts (4).
  • This is a reanalysis: Cisco was not executed in this run. Its reports were copied from `results/cisco_dataset_runs/agent_skills_sample/runs/2026-11-03_173516_sample30-seed2027` and analysed again with the current notebook code.
  • The manual-review worksheet was built from another run; it is attached here because worksheet was generated from run 2026-11-03_173516_sample30-seed2027; this run's manual_review_template.csv is byte-identical (same SHA-256), so the review IDs are the same.
  • Snippets and other text from skills are redacted where they look like secrets, and absolute local paths are rewritten as repository-relative ones. Cisco's raw reports (local only, not committed) keep the original text.

Glossary

Scan
One Cisco run over one skill in one configuration (skill x configuration).
Configuration
Scope (SKILL.md only, or the full skill folder) x analyzer mode (static, behavioral, LLM, meta).
Primary analysis
Uses only COMPLETE scans. Anything else is reported separately, never as zero findings.
Alert row
One finding Cisco reported in one scan. The same alert seen in four configurations is four rows.
Distinct alert location
Rule + file + line within one skill, merged across configurations. The unit used for review.
finding_kind
Our classification: security (counted as alerts), metadata_quality (license, description, naming) or scan_coverage (binary files, analysis-incomplete notes).
Evidence check
exact: Cisco's evidence is on the reported line; ambiguous / mismatch: it is elsewhere or unclear; unavailable: nothing to check. A pointer for reviewers, not a correction.
Comparison change
additional: present only in the later configuration (e.g. full folder); removed: only in the earlier one; unchanged: in both. Pairs are 'eligible' only when both scans are COMPLETE.
Redacted
Text that looks like a secret is replaced with [REDACTED] before it reaches any report file.
