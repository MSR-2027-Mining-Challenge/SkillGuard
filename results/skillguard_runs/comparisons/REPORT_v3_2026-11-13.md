**Fresh sample design.** Seed 2029, stratified 50 scripts / 25 supporting / 25 SKILL.md-only, with design weights recorded. It excludes all 120 skills used before (the dev 30 and held-out 2028's 90). An assertion checks there is no overlap.

## What V3 changed (fixes only from earlier error cases)

**False-positive fixes**
- **Negation:** "do not / never / instead of … spawn / `codex exec` / add to AGENTS.md" is no longer reported.
- **Verbs:** an exact verb-form list; the verb must come before the config path in the same sentence, within 120 characters. Dots inside filenames are no longer read as sentence ends.
- **Conditionals:** "do not ask *when* …" is not a bypass instruction.
- **Quoted metadata:** `description:`/`name:` lines outside the skill's own frontmatter are skipped. Data fences (JSON, YAML, TS, …) are skipped; prose fences are still scanned.
- **Flag opt-outs:** "disables --dangerously-skip-permissions" is not a bypass.
- **Shell parsing:** `[[ … ]]` tests, case labels, `command -v` checks and `if`/`then`/`do` keywords are handled correctly.

**New detections**
- **`agent_credential_access`:** `~/.claude/.credentials.json`, `.codex/auth.json`, Gemini OAuth files and the Claude keychain entry, in Python, shell (after resolving `VAR=` assignments), PowerShell and prose.
- **Wrapped agent launches:** `"${runner[@]}" claude`, `npx @anthropic-ai/claude-code`, `timeout … codex`, and `[*wrapper, "claude"]`.
- **PowerShell:** direct launches, launches built inside strings that are written to `.bat` files (marked `generated`, with `$var` flags resolved), scheduled tasks, `$env:CLAUDECODE=$null`, config writes and credential reads.
- **`$(…)`/backtick substitutions** are analyzed as their own commands. Scheduler listing (`crontab -l`, `launchctl list`) is reported as operation `list`.
- **`suspicious_agent_instruction`:** a heading block is flagged when it has at least 2 signals, one of them a core signal. Core signals are a future-session trigger, an instructional concealment phrase ("silently execute", "do not tell the user"), a pre-approval claim, an imperative HTML comment, hidden Unicode, or a disguised file. Remote fetch-execute and a raw-IP URL count as supporting signals. Evidence is kept as an excerpt plus the block's sha256.
- **Disguised scripts:** a `.py` file that fails to parse and looks like Markdown is scanned as text (`disguised_text_scanned`).

**Capability vs risk.** Each behavior keeps `assessment = needs_context` and adds `risk_signals` and `review_priority` (high / medium / low). Install docs collapse into one low-priority `installation_doc` behavior. A prose cron instruction attaches to the skill's scheduler behavior.

**Regression check.** On the dev sample and held-out 2028, V3 differs from V2 in 12 skills, and every difference is an intended fix or detection.

### V3 detections on unseen skills

- **skill-creator variant (`008695c2239c`):** strips `CLAUDECODE` to nest `claude -p` in 2 scripts, writes temp commands to `.claude/commands`, and spawns subagents. Neither V1-era rules (tuned on the dev copy) nor Cisco cover the nesting.
- **caveman-compress:** `subprocess` `claude --print` fallback, and README-described rewriting of `CLAUDE.md`.
- **wk-retro:** tells the agent to add a block to `$HOME/.claude/settings.json`.
- **contextsearch:** its example appends logs under `~/.claude/LIFEOS/MEMORY`.
- **harness-cli** and **skill-00998d1a3d74:** worker-agent and subagent spawning.
- **patent-disclosure-writer:** a user guide running `claude --dangerously-skip-permissions`.
- **`suspicious_agent_instruction`:** 0 detections on the fresh sample. The many descriptive "silently …" lines in other skills (12 files) were correctly ignored. With no positives in this sample, the detector's recall on new data is untested.

### V3 false positives and misses (provisional)

**False positives (2):**
- `agent-sdk`: an SDK option table that mentions `bypassPermissions`.
- `harness-cli`: "it is not the same as `bypassPermissions`".

Both come from one gap: negation and contrast checks are not applied to permission-flag mentions.

**Misses:**
- `full-nfr` (Chinese "派 … fresh subagent") and `gstack-team` (a `communicate { spawn: … }` tool call; Russian "поднять sub-agent"). Spawn detection is English-only.
- `design-reviewer`: a weak case with no spawn verb.
- `wk-retro`: "Add to `$HOME/.claude/memory/`" inside a Mermaid fence. V2 found it; V3 treats Mermaid as data.
- `caveman-compress`: the code-level `CLAUDE.md` write, whose path comes from a runtime argument.

**Priority mis-tag:** caveman's README describes real behavior but was tagged `installation_doc` (low priority).

### Cisco comparison

- Cisco and V3 do not overlap: 0 of 15 V3 behaviors are within ±3 lines of a Cisco security finding.
- Cisco's findings are general patterns (network calls, `child_process`, unpinned dependencies, YARA). In the 30-item sample, most correctly identify a pattern but are not security-relevant in context. Its clear errors include "autonomy abuse" on log lines and "command injection" on a constant `execSync`.
- Cisco is about 590 times slower per skill, but covers JS/TS and many more general categories.

## Limitations

- **All metrics are provisional AI labels** from the same assistant that built the tool. They are likely biased in V3's favor. The human-review package exists for exactly this reason.
- **Recall is bounded by a keyword sweep** plus my reading. Behaviors that use none of the swept keywords would be missed by both me and the tool. The 20-skill human recall audit addresses this.
- **Cisco precision sample:** `random.Random(7).sample(sorted(cisco item_ids), 30)` over the 108 blind items; the 30 IDs are the `cisco` rows of `provisional_ai_labels.csv`.
- **Small numbers:** 15 V3 behaviors and 30 sampled Cisco items give very wide confidence intervals; for example, 12/15 has a 95% Wilson interval of about 55–93%.
- **Not population estimates:** the sample is stratified with scripts over-sampled. Design weights are in the manifest.
- **Untested on new positives:** the suspicious-instruction, credential, PowerShell and disguised-file detectors had no positives in the fresh sample. Their regression tests and held-out-2028 cases are their only evidence so far.
- **Same database:** the fresh sample comes from the same GitSkills sample DB as the 13k-skill study population (the study's outputs were not used).
- **Minor:** `ast.parse` prints `SyntaxWarning` messages for some skill strings. They are harmless, but the warnings should be silenced.

   - limit `installation_doc` to text that tells a human to install the skill
