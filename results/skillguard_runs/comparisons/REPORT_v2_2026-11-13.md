## What changed in V2

1. **Behavior grouping.** There is one finding per call site; runtime-selected CLIs are listed inside it, with `trust_by_command`. `scan()` now returns `behaviors`, grouped per skill by capability and key. Config writes are merged when their agent-config roots overlap, and the same behavior in two scripts becomes one behavior with two locations. Doc examples and instructions attach to a matching code behavior as `documentation`; otherwise they form `documented_example` or `instruction_only` behaviors.
2. **Branch-aware folding.** Each value carries the `if`/`else` branch context it came from. Variables only take values from compatible branches, and concatenations and `/` joins only combine compatible parts.
3. **Markdown instruction layer** (heuristic, carrier `markdown_instruction`). It scans prose, non-code fences and inline code for:
   - `cronjob(...)` calls and "schedule cron jobs" phrasing
   - subagent, Agent Teams and Task spawning
   - inline agent CLI commands
   - permission flags and no-confirmation phrases, under a new capability `approval_bypass_instruction`
   - write verbs next to agent config paths (EN plus a few RU stems), and "block for AGENTS.md:" lines followed by a fence

   It also adds `~/.hermes` to the config paths, and treats agent tool calls written as Python (`cronjob`, `terminal`, `Task(subagent_type=…)`) as sinks.
4. **Generated code.** Multi-line string literals that parse as Python (after `{{ }}` unescaping), or that start with a shell shebang, are analyzed with `execution_context = generated` and correct line numbers. Docstrings are skipped.
5. **Indented fences.** Each fence's indentation is stripped before parsing (CommonMark rule, then dedent).

Every fix has regression tests, and each fix also has benign controls, for example prose that only reads `AGENTS.md`, `without asking for an API key`, docstrings with code, and a sink inside a benign branch.

### Held-out false-positive causes (7)

| Cause | Example |
|---|---|
| Negation | "Do not call `codex exec`" (web-access) |
| Verb over-match | "appends", "(installed skills)", "§ Runtime Package Installation" (claude-collab, paiupgrade, stata) |
| Conditional phrase | "do not ask **when** the user already specified" (resume-project-miner) |
| Quoted example | Another skill's description quoted in a reference (skillify) |
| Shell parser | `[[ $name =~ anthropic\|claude ]]` split on `\|` and read as a `claude` command (skillify) |

A further 4 behaviors are README install instructions for humans (`cp -r … ~/.claude/skills`). They are true text but low value. One install action is also split into 2 behaviors (cursor and claude roots).

### Held-out misses (`missed_behaviors_heldout.csv`; found by a keyword sweep, so recall is an upper bound)

- **usage `probe.sh`** reads the Claude OAuth token from `~/.claude/.credentials.json` and writes into `~/.claude/cache` through `$CACHE`. Shell variables are not resolved, and credential access is not a family. Cisco flags lines 33/41 of the same script as fetch-execute/taint.
- **claude-collab** has 2 of its 4 launches behind a `"${runner[@]}" claude` wrapper array.
- **fork-terminal** builds `--dangerously-skip-permissions` in `.ps1`, which is unsupported. Only the docs were caught.
- **security-scan** reads `crontab -l` and `launchctl list` inside `$(...)`. This is a benign audit, but it is not tokenized.
- **user-thoughts** says "use subagents" with no spawn verb.
- **mochat** says "No need to ask the owner", which isn't covered by the no-confirmation phrases. Its cron instruction and crontab example also split into 2 behaviors (key `cron` vs `crontab`).
- **ecommerce-email-quote** has `scripts/_resume_init.py`, which is Markdown inside a `.py` file, and `memory.md`. Both contain "deferred action" instructions telling a future agent session to silently fetch a script from a hard-coded IP and pipe it to bash. This is out of V2's families, and an unparsable `.py` file is not passed to the instruction layer. Cisco reports only `FILE_MAGIC_MISMATCH` on the `.py` and a generic `PIPELINE_TAINT_FLOW` on `memory.md`.

Approximate H1 behavior recall for agent-directed in-family behaviors is 4/7 (57%), counting usage, security-scan and user-thoughts as misses.

## What this says

- V2 fixes the counting problem: 21 rows on dev become 4 code behaviors plus attached docs. It also fixes the impossible paths and the indented-fence bug, and it detects generated code and Markdown instructions.
- **On unseen random skills, the instruction layer is noisy.** 6 of 13 H1 text behaviors are FPs, and 4 more are human install docs. Code-level detection is sparse (2 behaviors in 60 skills). The real agent-specific signal is mostly instruction-level, as expected.
- **SkillGuard and Cisco remain almost disjoint.** 1 of 22 held-out V2 behaviors overlaps Cisco, and Cisco covers JS/network/supply-chain rules that SkillGuard doesn't.
- The most security-relevant held-out item (the hidden deferred-action payload) was caught by neither tool in substance.

## Next experiment (recommended)

Fix only the held-out error causes listed above:
- handle negation and conditionals
- tighten the write-verb list
- tokenize `[[ ]]` and `$(...)` correctly
- unwrap wrapper arrays
- route unparsable `.py` files to the instruction layer
- add `agent_credential_access`
- add hidden-instruction / remote-execution patterns
- tag `README` install docs separately

Then **draw a fresh held-out set** (new seed, excluding dev and both current held-out sets, about 100 random skills) and have a human label it blind before running V3. This keeps the current held-out results honest and gives a real precision/recall estimate before the 1,000-skill run.
